# 공기 앱 지원·개인정보 페이지 설계

작성일: 2026-08-02

## 목표

App Store의 지원 URL과 개인정보처리방침 URL로 사용할 수 있는 공개 HTTPS
페이지를 Restato 사이트에 추가한다. 페이지는 현재 제출하는 `공기 — 미세먼지와
예보` 1.0의 실제 동작만 설명하고, 아직 포함되지 않은 광고·계정·분석·유료 기능을
암시하지 않는다.

## 경로와 역할

- `/apps/air-quality/support`: 앱 소개, 주요 기능, 자주 묻는 질문, 문제 신고 시
  필요한 정보, 지원 이메일 `direcision@gmail.com`을 제공한다.
- `/apps/air-quality/privacy`: 데이터 처리 주체, 위치 및 장소 검색 데이터 흐름,
  로컬 저장과 삭제, 제3자 제공처, 보유 기간, 이용자 권리, 정책 변경일을 제공한다.

두 페이지는 서로 연결하고 홈으로 돌아가는 이동 경로를 제공한다. App Store에는
각 목적에 맞는 직접 URL을 입력한다.

## 콘텐츠 원칙

### 지원 페이지

- 앱이 현재 위치 또는 직접 찾은 장소의 공기 상태, 미세먼지, 예보, 위젯과
  Apple Watch 정보를 제공한다고 설명한다.
- 위치 권한 없이도 장소 검색을 사용할 수 있음을 안내한다.
- 데이터는 건강 진단이나 응급 판단을 대신하지 않는다고 명시한다.
- 문의 시 앱 버전, 기기와 OS 버전, 문제 발생 시각, 재현 단계를 보내도록
  안내하되 위치 좌표나 민감정보를 보내도록 요구하지 않는다.

### 개인정보처리방침

- 처리 주체는 Restato 개인 개발자이며 연락처는
  `direcision@gmail.com`이라고 밝힌다.
- 현재 1.0에는 계정, 광고, 타사 추적, 분석 SDK가 없다고 명시한다.
- 사용자가 기능을 실행할 때 위치 좌표·시간대·장소 검색어가 Open-Meteo의
  공기질 및 지오코딩 API로 직접 전송될 수 있음을 설명한다.
- Open-Meteo와 CAMS 출처 및 Open-Meteo의 자체 로그·보유 정책 경계를
  명시하고 공식 개인정보/약관 링크를 제공한다.
- 저장 장소와 정규화된 공기질 캐시는 사용자의 기기/App Group에만 저장되며,
  장소 삭제 또는 앱 삭제로 제거할 수 있다고 설명한다. 현재 출시 구성에는
  개발자 운영 계정 서버나 CloudKit 동기화가 없다.
- Apple Watch에서 저장 장소를 새로고침할 때 같은 제공처로 위치가 전송될 수
  있음을 밝힌다.
- 지원 이메일로 접수된 문의는 답변과 분쟁 처리에 필요한 기간만 보관한다고
  설명한다.

## 화면 설계

기존 `MainLayout`과 PasteDock 정책 페이지의 패턴을 재사용한다. 상단에는
하늘색에서 민트색으로 이어지는 옅은 배경과 앱 이름을 사용하고, 본문은
`max-w-4xl` 카드 묶음으로 구성한다. 작은 화면에서는 한 열, 큰 화면에서도
긴 법률 문장이 읽기 쉬운 한 열을 유지한다. 링크와 이메일은 밑줄뿐 아니라
충분한 색 대비와 명확한 텍스트를 사용한다.

## 오류와 변경 관리

- 존재하지 않는 기능이나 확정되지 않은 보유 기간을 넣지 않는다.
- 광고, 분석, 알림 서버, 로그인 또는 데이터 제공처가 추가되면 앱 출시 전에
  정책을 먼저 갱신한다.
- 페이지 하단에 최종 갱신일을 표시한다.

## 검증

- `npm run build`로 두 Astro 경로와 사이트맵 생성을 검증한다.
- 생성된 HTML에 지원 이메일, Open-Meteo, 추적 없음, 광고 없음, 위치 데이터
  흐름, 최종 갱신일이 포함되는지 확인한다.
- 로컬 미리보기에서 모바일과 데스크톱 레이아웃, 키보드 링크 이동, 색 대비를
  확인한다.
- 배포 후 두 HTTPS URL이 로그인 없이 HTTP 200으로 열리는지 확인한 다음
  App Store Connect에 입력한다.
